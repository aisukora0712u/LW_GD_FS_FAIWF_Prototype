# 路线图与容量护栏

## 产品容量包络

“《杀戮尖塔》相当规模”在这里表示中型、内容驱动、可重复游玩的单机产品，不等同于一次性承诺具体数量。建议在垂直切片数据稳定后，从以下包络中确定正式预算：

- 2–4 个可玩角色或核心构筑流派。
- 150–350 张可收集卡牌/等价能力。
- 40–80 个敌人与首领变体。
- 3–4 个主要章节/区域。
- 80–200 个叙事事件，或按分支口径约 10–25 万字。
- 8–20 小时首次通关内容，长期重复游玩由构筑、随机事件和难度层提供。

这些数字是规划边界，不是当前承诺。每种内容都必须有单位制作成本与维护成本测量。

## 阶段 0：生产底座（本地能力已建立，远端协作未验证）

完成条件：架构边界、任务协议、RFC/ADR、内容管线设计、本地检查和 CI 入口可用；团队能用同一套完成定义交付任务。

2026-09-05 审计：GitHub 远端和个人 CODEOWNER 已建立并执行首次框架同步；组织团队、Runner、Ruleset 与真实 CI 运行仍未验证，不能把配置存在视为团队交付能力完成。证据与剩余项见 [全栈就绪审计](Production/READINESS-AUDIT.md)。

## 阶段 1：可玩内核（已完成基础闭环）

实现确定性战斗状态机、卡牌/效果模型、回合与目标规则、事件日志，并以纯 C# 测试覆盖核心组合。不追求精美表现。

截至 2026-09-01，已实现稳定内容 ID、命名随机流、抽牌/弃牌/洗牌、费用、伤害、格挡、敌方回合、胜负、结构化战斗事件，以及视觉小说节点、条件选择、变量与跨玩法命令。扩展状态效果和复杂触发器前需另立 RFC。

## 阶段 2：垂直切片（当前）

15–20 分钟内容：1 个角色、12–20 张卡、3 个普通敌人、1 个首领、3–5 个叙事节点、1 条短地图路线。贯通奖励、存档、读档、本地化和基础设置。关键路径无阻断错误，可完整重放一个种子。

当前进度：已贯通叙事、地图、多场战斗、奖励、升级、商店、遗物与 Boss，包含双语界面、内容审阅、叙事拓扑校验和安全存档。正式容量、设计审批、设置/无障碍、视听资产和性能验收仍未完成；不能因样例通过门禁而宣称阶段 2 完成。

## 阶段 3：生产验证

让非程序角色通过内容源新增一张卡、一个敌人和一个分支事件；导入、校验、预览、测试与构建在一天内完成。根据真实工时调整容量预算。

## 阶段 4：规模化生产

按双周可玩增量扩展章节和内容。每次增量保持绿色构建，持续跟踪胜率、选择率、内容覆盖、软锁、崩溃、加载和内存指标。

## 阶段 5：Alpha / Beta / 发布

- Alpha：所有系统和内容入口存在，可从头到尾完成。
- Beta：内容锁定，只做修复、平衡、性能、本地化和兼容性。
- Release Candidate：存档迁移、平台功能、回滚包、商店资产和发行清单全部通过。
