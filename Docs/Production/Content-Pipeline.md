# 视听内容交接与可选 3D 规范

## 适用范围

视觉小说、卡牌等规则与文本遵循 [结构化内容管线](CONTENT_PIPELINE.md)，不需要为每个节点、卡牌或遭遇创建独立 3D 场景。本页处理视听资产交接；下方坐标、LOD、灯光和场景拆分仅适用于使用相应资产的任务。

工程基础设施不决定产品美术风格或发行平台。正式方向由负责人确认；在确认前只能制作明确标注的候选，不得以占位素材或工程默认值充当已批准资产。

## 视听任务交接

所有类型均记录稳定资产 ID、任务/内容版本、负责人、源文件、导出文件、来源/许可、目标显示或播放情境、人工审批依据和回滚文件。AI 生成资产须记录工具、模型、输入来源与提示词摘要；不得提交凭据或未经确认授权的参考素材。

| 资产类型 | 作者交接与集成检查 | 人工验收证据 |
| --- | --- | --- |
| VN 立绘、表情、背景 | 尺寸/透明通道、角色与表情 ID、文本遮挡区域、切换映射 | 目标宽高比下的对白画面、表情与剧情匹配审阅 |
| 卡面、图标、UI | 原图与导出图、裁切/安全区、卡牌 ID 映射、小尺寸辨识 | 实际手牌与详情视图、双语长文本、对比度与非颜色提示 |
| 动画、特效 | 状态/事件映射、时长、循环/打断规则、候选资源引用 | 实际触发、取消/快进、视觉舒适性及性能捕获 |
| 音乐、音效、语音 | 源音频、导出格式、事件/台词 ID、语言、循环点与混音意图 | 实际播放、循环接缝、音量控制、字幕/台词对应 |

顺序沿用 [AI 交接协议](AI-HANDOFF.md)：隔离候选和来源检查 → 负责人批准 → 集成预览 → 回归与构建。现有 JSON 候选工具不导入图片或音频；表中检查仍须执行并留证，不能用 JSON 审阅报告替代。目标分辨率、压缩、响度、帧率与容量由任务规格确定，本文不新增数值承诺。

集成前保留上一版源文件和 Unity `.meta`，避免无意改变 GUID。导入默认值由 `ProductionAssetPostprocessor` 应用，包括按 `/UI/` 判断 Mipmap、按 `/Music/` 判断流式音频；路径约定不是自动识别素材用途。当前后处理器会在重导入时重新赋值，持久例外需要经审阅的导入策略实现，不能仅手改 Importer 后宣称已固定。

## 可选 3D：坐标与命名

- 1 Unity Unit = 1 米；Y 向上，角色面向约定的本地 +Z。
- 文件采用 `Category_Descriptor_Variant`，禁止 `final2`、`new` 等时间性命名。
- 枢轴、碰撞体、LOD、材质槽和骨骼命名在 DCC 出库前完成。
- 源文件放入 `Assets/_Game/ArtSource` 并由 LFS 管理；游戏直接加载的资产进入 `Content`。

## 可选 3D：场景拓扑

采用关卡场景工作流时，按以下职责拆分：

- `Level_Name`：碰撞、玩法实体、导航和关卡逻辑。
- `Level_Name_Lighting`：灯光、探针、烘焙设置。
- `Level_Name_Presentation`：装饰、特效、氛围音频和非玩法表现。
- `Persistent`：跨关卡但不持有具体关卡状态的系统。
- `Bootstrap`：组合根，必须是 Build Settings 第一场景。

该工作流中的关卡必须有 `LevelProductionProfile`，明确负责人、帧率、内存、加载、GC、光照和导航策略。现有工程采用 60 FPS 初始目标，是否满足正式平台需要实测及负责人确认。预算例外通过带期限和负责人的 ADR/Issue 批准。当前校验器对启用的 `/Levels/Level_` 主场景检查配置，不把数据目录的路线节点当作 Unity 场景。

## 导入与评审

编辑器自动应用模型、纹理和音频默认值，不代表符合每种内容的需求。特殊资产的持久导入策略须在 PR 中说明理由并验证重导入行为。

- 模型：默认不可读、不导入 DCC 摄像机和灯光；LOD 与碰撞单独评审。
- 纹理：非 UI 默认 Mipmap 与 Streaming；平台压缩在垂直切片阶段冻结。
- 音频：音乐流式播放，短音效压缩到内存；语音和多语言容量单独预算。
- Prefab：采用小型组合，禁止整关巨型 Prefab 和深层 Variant 链。

视觉评审同时检查目标画质、帧时间、显存、过度绘制、灯光数量、Shader Variant 和包体变化。
