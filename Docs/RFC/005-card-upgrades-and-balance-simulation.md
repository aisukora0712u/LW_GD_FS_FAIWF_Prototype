# RFC-005：卡牌升级节点与确定性平衡模拟

- 状态：Accepted for implementation
- Owner：Gameplay / Systems Design / QA
- Reviewers：Content / Engineering
- 最后更新：2026-09-01
- 关联 ADR：ADR-002

## 玩家价值

玩家需要在加牌之外主动改造牌组；设计与 AI 内容代理则需要在人工试玩前用大量固定种子发现不可通关、胜率漂移和回合数离群内容。

## 目标

- 卡牌可通过稳定 ID 声明一个升级目标，且目标必须存在、不能自引用。
- 路线支持 Rest 节点；进入后必须选择一张可升级牌，替换后回到地图。
- 升级后的牌组进入安全存档，并在后续战斗实际使用新定义。
- 提供确定性自动玩家，批量执行完整 Run，并输出机器可读 JSON 报告。
- 报告至少包含样本数、胜率、完成/战败数、平均剩余生命、平均战斗回合、各路线选择与卡牌使用次数。

## 非目标

- 本轮不决定正式升级树、移除牌、商店经济、遗物或最终 AI 策略。
- 自动玩家不是玩家行为预测，只是稳定的回归探针；统计不能替代设计负责人判断。
- 不让生成内容因模拟分数自动变为 approved。

## 验收标准

- [x] Rest 只允许升级当前牌组中声明了合法目标的牌，成功后只替换一个实例并离开节点。
- [x] 升级状态可存档恢复，后续战斗读取升级后的费用和效果。
- [x] 相同种子范围产生逐字节一致的规范化报告。
- [x] 不可通关样例能在报告与测试中被识别。
- [x] CLI 可指定样本数、起始种子和输出路径。
- [x] 内容、本地化、EditMode、PlayMode、完整门禁与 Windows 构建通过。

## 风险与回滚

启发式自动玩家可能低估组合牌。报告需标记策略版本，只比较同一策略的基线。回滚时移除 Rest 路线、升级映射、模拟器及 content schema v3；恢复 vertical-slice.2，存档 schema v2 不需降级。
