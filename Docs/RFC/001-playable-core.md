# RFC-001：确定性卡牌与叙事可玩内核

- 状态：Accepted for implementation
- Owner：Core Gameplay
- Reviewers：Design / Narrative / Engineering
- 最后更新：2026-09-01
- 关联任务：阶段 1 可玩内核

## 背景与玩家价值

项目需要让卡牌战斗与视觉小说共享稳定内容身份、可保存状态和可重放事件。当前工程只有平台底座，无法表达一次可验证的玩法状态转换，也无法让内容工具安全地产生规则数据。

## 目标

- 以纯 C# 实现稳定内容 ID 与命名确定性随机流。
- 实现最小卡牌战斗闭环：抽牌、费用、伤害、格挡、弃牌、洗牌、敌方回合、胜负。
- 实现最小视觉小说闭环：节点、条件选择、变量、内部命令、跨玩法命令和终止。
- 每个状态变化产生有序事件，支持测试、调试和未来重放。
- API 不依赖 MonoBehaviour、ScriptableObject、场景或显示文本。

## 非目标

- 本轮不决定正式卡牌、角色、敌人、世界观或数值平衡。
- 不实现状态效果、复杂触发器、AI 决策、地图、奖励或 Meta 进度。
- 不实现内容导入器、Unity UI、动画、存档 DTO 或网络同步。
- 不允许内容执行任意 C#、反射、脚本表达式或动态代码。

## 玩家流程

1. Run 使用根种子创建 `combat.draw` 等命名随机流。
2. 战斗启动并抽取初始手牌；玩家打牌或结束回合。
3. 所有规则更新写入事件日志；战斗最终进入 Victory 或 Defeat。
4. 叙事从稳定节点 ID 开始，仅展示条件成立的选项。
5. 选择更新故事变量，并输出诸如 `GrantCard`、`StartCombat` 的受限跨玩法命令。
6. 上层 Gameplay 编排器消费跨玩法命令，Core 不直接加载场景或资源。

## 规则与边界情况

- 内容 ID 使用小写分段格式，例如 `card.iron_strike`；空 ID、空分段和非法字符立即拒绝。
- 相同根种子与流名必须产生相同序列；不同流互不消耗状态。
- 卡牌必须有非负费用和至少一个合法效果；费用不足、目标无效或战斗阶段错误不改变状态。
- 伤害先消耗格挡；玩家格挡在新玩家回合开始时清零。
- 抽牌堆为空时以 `combat.draw` 洗入弃牌堆；手牌满时抽到的牌进入弃牌堆。
- 叙事条件只读取显式变量；缺失变量不满足任何比较。
- `SetVariable` 与 `AddInteger` 在 Core 内执行；跨玩法命令只入队，不产生隐式副作用。

## 数据与内容

定义与状态严格分离。定义通过稳定 ID 关联，状态未来保存根种子、各命名流状态、牌堆顺序、战斗实体、故事变量、当前节点与内容版本。此 RFC 不改变现有存档 schema。

## 技术方案

实现位于 `Game.Core`，保持 `noEngineReferences=true`。Unity 内容资产、导入器与表现层在后续 RFC 中适配这些纯 C# 定义。事件使用结构化枚举与字段，不把本地化文本写入领域日志。

## 表现、音频与无障碍

Core 只提供结构化状态与事件。表现层必须允许加速/跳过已读叙事、关闭动画、键盘/手柄操作，并使用本地化键渲染文本；具体方案进入垂直切片 RFC。

## 遥测与调试

事件保留单调递增序号、回合/节点、来源、目标、内容 ID 和数值。Bug 包未来记录根种子、流状态、内容版本与最近事件。事件日志不含玩家输入文本或个人数据。

## 验收标准

- [x] 相同种子重复启动战斗，手牌顺序和事件序列一致。
- [x] 打出攻击/格挡/抽牌卡时，费用、牌堆与角色状态正确更新。
- [x] 非法命令返回明确错误且状态不变。
- [x] 敌方回合可导致下一回合或 Defeat，消灭全部敌人进入 Victory。
- [x] 叙事选择按变量过滤，并能更新变量、跳转节点和输出跨玩法命令。
- [x] `Game.Core` 仍无 Unity 引用，新增规则由 EditMode 测试覆盖。

## 验证计划

- 单元/规则测试：内容 ID、随机流、战斗成功/失败路径、洗牌、叙事条件/命令/终止。
- 内容校验：本轮由构造器保证最小不变量；批量 schema 校验后续实现。
- PlayMode/冒烟：现有 Bootstrap 测试保持通过。
- 人工体验：后续垂直切片 UI 接入后执行。
- 性能预算：单次规则命令不分配 Unity 对象；规模化模拟预算后续建立。

## 风险与回滚

主要风险是过早固化复杂效果语言。本轮只提供小型白名单，并以新增枚举/处理器演进。所有新类型均未进入已发布存档，可通过移除新增 Core 文件回滚。

## Open Questions

- 正式卡牌效果组合采用数据列表、效果图还是编译代码生成。
- 叙事外部命令何时暂停节点推进，由 Gameplay 编排 RFC 决定。
- 状态效果、触发优先级与无限循环预算在战斗扩展 RFC 中决定。
