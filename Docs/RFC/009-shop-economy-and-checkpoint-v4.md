# RFC-009：确定性商店经济、删牌与 checkpoint v4

- 状态：Implemented and verified
- Owner：Gameplay / Systems Design
- Reviewers：Content / UI / QA
- 最后更新：2026-09-02
- 关联 ADR：ADR-002

## 玩家价值

金币必须形成真实构筑决策，而不是只存在于剧情变量。商店让玩家在购买新牌、精简牌组和保留资源之间权衡，并验证经济状态能跨节点安全恢复。

## 目标

- 内容定义商店商品池、卡牌价格、删牌价格与展示数量。
- 进入商店时用 `shop.N` 命名随机流生成确定性、去重库存。
- 玩家可购买库存牌；金币不足、未知商品或重复购买不改变状态。
- 每个商店最多删牌一次，且不能把牌组删空。
- 玩家可随时离开商店并继续路线。
- checkpoint v4 保存商店 ID、库存、商店序号与删牌状态，并逐版本迁移 v1→v2→v3→v4。
- UI 双语显示金币、商品、删牌和离开操作；自动玩家会执行一项经济决策。

## 非目标

- 本轮不实现动态折扣、药水、遗物售卖、补货或多货币。
- 样例价格和自动玩家购买策略不是正式经济平衡。

## 验收标准

- [x] 相同根种子和商店序号生成相同库存，不同流不影响战斗/奖励随机。
- [x] 购买与删牌原子扣除金币并更新牌组；失败命令不改变任何状态。
- [x] 商店中 checkpoint v4 往返保留库存、删牌状态和金币，v1-v3 可迁移。
- [x] 内容引用/价格/库存数量非法时阻断导入。
- [x] 双语 UI 和 PlayMode 覆盖进入商店、购买或删牌、离开并进入 Boss。
- [x] 模拟 0 卡死，完整 Workflow 与 Windows Development 构建通过。

## 回滚

移除 Shop 路线、目录、RunPhase、UI、模拟策略和 schema v6 内容，恢复 checkpoint v3；v4 存档不能静默降级。
