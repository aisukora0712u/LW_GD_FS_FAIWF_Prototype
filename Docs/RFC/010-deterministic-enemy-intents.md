# RFC-010：数据驱动的确定性敌人意图

- 状态：Implementation in progress; design approval pending
- Owner：Gameplay / Systems Design
- Reviewers：Content / UI / QA
- 最后更新：2026-09-04
- 关联 ADR：ADR-002

## 玩家价值

卡牌战斗需要让玩家根据敌人下一步行动决定攻击、防御或控制。固定每回合攻击无法形成足够的可读决策，也使自动平衡模拟低估防御和状态牌的价值。

## 目标

- 每个敌人由内容定义一个至少包含一个意图的循环；每个意图具有稳定 ID 和有序效果列表。
- 首回合开始前即可读取当前意图；敌人行动后才推进到下一个意图，循环到末尾后回到开头。
- v1 支持 `Attack`（玩家）、`GainBlock`（自身）和 `ApplyStatus`（玩家或自身）。
- 同一意图的效果按作者顺序执行，事件日志保留意图 ID、来源、目标、数值和状态。
- 多敌人仍按 encounter 中的稳定顺序行动；已击败敌人不执行或推进意图。
- content schema v7 删除固定 `attackDamage`，要求合法的意图、目标与状态引用。
- 双语 UI 预告完整当前意图；自动模拟继续使用相同 Core 规则。

## 非目标

- 本轮不实现加权随机意图、条件分支、召唤、逃跑、多段动画时间轴或战斗中存档。
- 样例意图数值与循环不是最终平衡结论。

## 规则顺序

1. 玩家结束回合并弃牌，既有状态按当前已批准窗口衰减。
2. 每个存活敌人清除上回合自身格挡。
3. 按当前意图的作者顺序执行效果；致死后立即终止剩余敌人行动。
4. 成功完成行动的敌人推进意图索引。
5. 全部敌人完成后进入下一玩家回合，UI 展示推进后的意图。

## 验收标准

- [ ] Core 测试证明预告、顺序执行、循环、死亡短路和多敌人顺序确定。
- [ ] Attack 继续服从 Strength→Weak→Vulnerable→Block 顺序；GainBlock 与 ApplyStatus 产生完整事件。
- [ ] schema/解析器拒绝空循环、重复意图 ID、非法目标和缺失状态引用。
- [ ] 三个样例敌人具有不同循环，双语 PlayMode 能看到并执行非攻击意图。
- [ ] 200 种子模拟 0 卡死，完整 Workflow 与 Windows Development 构建通过。

## 回滚

恢复固定 `attackDamage` 敌人定义、content schema v6、旧 UI 与 CombatState 敌人行动；schema v7 内容不得被旧运行时静默接受。

## 审批与当前验证边界

意图循环、样例数值与状态窗口是设计提案，尚无负责人确认记录，不应视为已批准的正式玩法。源文件的 `approved` 标签不能代替人工审批证据。

2026-09-04 审计发现完整路径测试采用手牌顺序策略，而平衡模拟使用效果评分策略；不能单凭前者战败就推断内容不可通关，也不能为通过该固定种子反复修改正式数值。新增失败事件轨迹记录种子、回合、出牌、意图、格挡和伤害，用于区分规则缺陷、策略限制与数值问题。当前不声明本 RFC 验收完成。

本次 EditMode 实跑 66 项，65 通过、1 失败。seed=4242 的 Boss 轨迹中，第 2/5 回合在敌人格挡意图前出防御牌，第 8 回合在同类意图前连续出三张防御牌，最终第 9 回合战败。这证明固定策略未利用意图信息；不单独证明数值合理或引擎无缺陷。下一步应增加可重复的意图感知策略对照，并在不改变数值和验收断言的前提下比较完整事件轨迹。
